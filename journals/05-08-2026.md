## GNSS failure investigation

- The user reports that GPS/GNSS does not work on the installed TRY25 baseline. This is tracked as `ODESSA-007` (`P2`).
- The device is available over Android ADB. Investigation will avoid collecting or retaining precise coordinates, NMEA sentences, device identifiers, or account data. No partition write was authorized or performed.
- Read-only TRY25 ADB inspection shows `android.hardware.gnss@2.1-service-qti`, `loc_launcher`, `mlid`, `lowi-server`, and `xtra-daemon` running. `lshal` reports the declared Android and vendor GNSS HIDL instances registered with VINTF device/framework matches.
- `dumpsys location` reports 7,206 processed satellite-status messages but zero location reports, TTFF reports, position-accuracy reports, CN0 reports, used-in-fix satellites, and GNSS measurement events. The snapshot had no active request when collected. No coordinates or NMEA data were collected or retained.
- This rules out a missing GNSS service, manifest, or basic modem callback path as the first explanation. The leading investigation area is now acquisition/reporting between the legacy open-source HAL and the proprietary Qualcomm location libraries, followed by the newer Qualcomm AGPS/configuration fixes.
- A second read-only inspection found the active boot slot is `_a`; modem-super-image and FSG-super-image properties are unset. `/proc/mounts` shows `/vendor/firmware_mnt` from `sde17`, `/vendor/dsp` from `sde18`, `/vendor/bt_firmware` from `sde19`, and `/vendor/fsg` from `sde16`, so the regular firmware paths are mounted. Direct `mountpoint`/directory checks remain restricted by shell permissions.
- Location is enabled (`settings secure location_mode=3`, `cmd location is-location-enabled=true`). The location-manager history records repeated `org.lineageos.aperture` GPS requests and a `com.android.gpstest.osmdroid` high-accuracy request from 18:02 to 18:06, plus a full-tracking GNSS measurement request; each recorded zero locations. Coordinates were not read.
- The generated TRY25 vendor output contains five non-GNSS seccomp policies, while the common GPS source declares four GNSS policy modules but its product makefile does not package them. TequilaOS also contains the same five non-GNSS policies, and `gnss_service` already runs on TRY25, so this is a packaging-parity issue rather than the leading explanation for the no-fix failure.
- Source comparison against Qualcomm `hardware/qcom/sm7250/gps` `c0e0375f06c0335062f19e3d87cb84d3c27cbc57` found applicable later fixes for AGPS subscriber teardown, optional WDS PDN-type lookup, emergency SUPL APN handling, and MBN-owned LPP configuration.
