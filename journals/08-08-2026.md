## Hotspot Root Cause And Candidate Fix

- Reproduced hotspot association and DHCP after the manual reboot, but the
  connected client had no Internet access.
- While tethering was active, `dumpsys tethering` timed out and Settings again
  lost Tethering callback progress. A read-only NetworkStack stack dump showed
  its `droid.tethering` handler blocked indefinitely in
  `OffloadHalHidlImpl.getIOffloadHal()`.
- The packaged `ipacm` process was running and had registered
  `IOffloadConfig` 1.0. It could not register its implemented
  `IOffloadControl` 1.1 because the device manifest declared control 1.0.
  Runtime repeatedly tried and failed to find the declared 1.0 control service.
- Updated the common-tree manifest declaration from tether-offload control 1.0
  to 1.1, matching the built `liboffloadhal` implementation and current
  LineageOS SM6150 device-tree practice. This is a source-level candidate only;
  build and hardware verification are pending.
- No hotspot credentials, network names, hardware addresses, or client
  identifiers were retained in project documentation.

## Newly Exposed Dnsmasq Spawn Failure

- Hotspot still rolled back after SoftAP/offload initialization. Netd logged
  `Failed to send update command to dnsmasq (Broken pipe)`, and no `dnsmasq`
  process remained alive.
- Android 16 bionic's `posix_spawn` path marks descriptors 3 and above close on
  exec with `close_range(3, ~0U, CLOSE_RANGE_CLOEXEC)` and exits 127 if that
  call fails.
- The running 4.14 kernel source has neither a `close_range` implementation nor
  native/compat syscall 436 entries. Device `strace` did not recognize the
  syscall name, and Magisk `su` was unavailable, so a direct runtime errno
  capture was not obtained. The source/runtime chain is strong but the candidate
  still requires build and hardware proof.

## Close-Range Kernel Candidate

- Added syscall 436 for native arm64, arm64 compat, and ARM tables; set native
  and compat syscall counts to 437.
- Added the standard `CLOSE_RANGE_UNSHARE` and `CLOSE_RANGE_CLOEXEC` UAPI flags,
  the syscall wrapper, and range close/cloexec fd-table operations.
- Reused the existing 4.14 `unshare_files()` implementation for
  `CLOSE_RANGE_UNSHARE`, avoiding the reference branch's unrelated fd-table
  allocator/API rewrite while preserving syscall semantics.
- `git diff --check` passes. The candidate is unbuilt and has no hardware result.
