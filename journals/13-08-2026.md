# 13-08-2026

## ODESSA-011 root cause

- Read-only checks on exact TRY34 (`1786476871`, slot A, SELinux enforcing)
  reconfirmed that Package Manager declares `android.hardware.sensor.compass`
  while the 39-entry framework sensor list contains no magnetic-field sensor.
- The Android sensor stack is otherwise healthy: the multihal, `sensors.qti`,
  calibration service, and ADSP sensor process run, and SSC-backed sensors work.
- The packaged `sdmmagpie_qmc6308_0.json` is selected for live platform `IDP`
  and SoC ID 365. Its generated registry describes I2C bus 1, slave value 44
  (`0x2c`), IRQ 119, and `/pmic/client/sensor_vddio`.
- Strings extracted read-only from the loaded `/vendor/firmware_mnt/image/adsp.b*`
  prove the ADSP firmware contains `sns_qmc6308` and its probe paths, including
  `Failed Open port`, `Read WHO-AM-I error`, and `Unsupported Sensor`. The failure
  is therefore not a missing QMC6308 DSP driver.
- The preserved `/mnt/vendor/persist/sensors/sensors_list.txt` is dated
  2020-07-12 and lists the sensors discovered by the original vendor stack. It
  includes accel, gyro, light, proximity, fusion, and Moto sensors, but no
  `mag`, magnetometer, or QMC6308. This predates the custom-ROM bring-up and is
  direct evidence that this exact XT2087-1 did not expose a magnetometer under
  stock discovery.
- Historical LineageOS 19.1 and the Tequila-derived blob set carry the same
  QMC6308 configuration, but that generic configuration does not prove the chip
  is populated on every Odessa SKU or board. Public specifications conflict;
  they are weaker evidence than the device's preserved stock discovery result.
- Root cause: `sm6150-common/common.mk` unconditionally advertises
  `android.hardware.sensor.compass` even though this exact device has no exposed
  magnetic-field sensor. Excluded that feature for `TARGET_PRODUCT=lineage_odessa` while
  retaining it for the other shared-tree devices. The QMC configuration is also
  retained because it is harmless and may cover another hardware variant.
- No device partitions or persistent files were modified. A future build must
  verify that Package Manager no longer declares the compass feature before
  resolving `ODESSA-011`.
